⚡ 全篇極簡核心考點總綱（六句話通透版 — 考場秒殺錨點）
1. 靠上下文語境理解詞義 Context & Semantic Priming
人類（特別是新手）極度依賴語境來消除歧義。提供正確的啟動詞（如 Cable ➔ Lock 指物理鎖，BIOS ➔ Lock 指密碼；計算機與 Nokia 手機上的 C）才能引導正確操作。
2. 不同人對同一字有不同理解 Lexical Ambiguity & User Groups
詞義頻率因人而異：POST 對新手是郵件 (Mail)，對專家是開機自檢；Scenario Manager 在金融師、UX 設計師和香港導演眼裡完全是三碼事！
3. 文字解釋抽象，圖案展示空間 Text vs. Image / Icons
圖標（Icons）不總是最佳選擇（如難懂的餐飲圖標、GroupWise 無標籤圖標）。文字比圖像精確得多，適合解釋抽象概念；圖案則適合空間定位，且圖標必須配文字標籤 / Tooltips！
4. 文字不要含糊，別說同義反覆的廢話 No Full Circle / No Synonyms
避免同義詞混用（Properties vs Options），也別寫「廢話文學」式的懸停提示（如 Properties = Show the properties、Quick Steps = Manage quick steps，邏輯正確但毫無解釋力）。
5. 絕對不要多重否定 Avoid Multiple Negations
反例：刪除精靈時彈出 "Not enough memory to allow undo... Continue without undo?"（五重否定逼用戶點 No 才能保留 Undo）。鐵律：陳述句必須用肯定句 (Affirmative)，把否定留給用戶按鈕！
6. 不要「左右腦互搏」（避免自相矛盾與心智衝突） Mental Model Clash & Contradiction
反例：點 [Start 開始] 去關機、點 View > Non-Visual Objects、Failed! (Operation succeeded)、正在 Cancelling... 還讓人點 [Cancel]、以及 CMHK 短信剛說付完款又叫人 pay the bill！

📖 Reading Text (= Visual Pattern Recognition) 閱讀三階段與語言三層次 Slides 3 - 7

核心定義 (Slide 4)："Text is an image with coded meaning."（文字本質上是一種帶有編碼意義的圖像！）而且圖標 (Icons) 並不總是最佳選擇，有時候文字描述比抽象圖標清晰得多（如 Slide 4-5 中讓人一頭霧水的 4 個餐飲圖標：Bar / Restaurant / Self Service / Snacks）。

1️⃣ 閱讀的三個認知階段 (Three Stages of Reading, Slide 4)

  • Stage 1: Visual pattern perceived (感知視覺模式) — 眼睛接收文字的幾何筆畫特徵（如古埃及聖書體、漢字「慧」、字母 i）。
  • Stage 2: Decoded using internal representation of language (內部語言表徵解碼) — 將視覺符號映射為腦海中的詞彙表徵。
  • Stage 3: Interpreted using knowledge of syntax, semantics, and pragmatics (結合句法、語義與語用知識解讀)。

2️⃣ 語言解讀的三個維度 (Syntactic / Semantic / Pragmatic, Slides 6-7)

  • Syntactic (句法層)：語言結構與語法規則，例如 Sentence = Noun_Phrase + Verb_Phrase 或代碼 Debug.Print text。
  • Semantic (語義層)：脫離語境的字面/非字面詞義，例如廣東話 "Sihk jó faahn meih a?" 字面意思是 "Have you eaten yet? (食咗飯未呀？)"。
  • Pragmatic (語用層)：結合對話參與者與具體情境 (Context) 的真實意圖——"食咗飯未呀？" 在社交偶遇時語用意思是 "How do you do? (打招呼)"，在家裡開飯時則是 "Sit and eat (坐低食飯)"！
    💡 代碼腐化案例 (Slide 7)：Semantics change due to Pragmatics — 隨時間推移，程序員複製舊註釋並修改底層 Scratch 代碼，導致代碼的實際語義因使用情境改變而偏離原意！

👁️ 眼動追蹤三機制 (Scanning / Saccades / Fixations) 與字體設計實驗 Slides 8 - 13

🔍 1. Scanning (全局掃視, Slides 8-9)

對文本及其結構進行全局探索 (Global exploration)，評估所需付出的精力 (Effort estimate：文字多不多？單詞長不長？)。若界面像 Monticello Browser (Slide 9) 那樣密密麻麻，Scanning 階段就會讓用戶崩潰。

⚡ 2. Saccades (眼跳, Slides 8, 10-12)

眼球快速跳躍——不僅順著閱讀方向跳，還會前後回跳 (Regression) 甚至上下跳動！此時單詞輪廓 (Word shape) 與字體 (Fonts) 對識別至關重要（如微軟 ClearType 抗鋸齒技術）。

🎯 3. Fixations (注視停頓, Slides 8, 13)

感知與理解「僅僅發生在注視停頓 (Fixations) 期間」（眼跳之間處於大腦空閒狀態 Idle state）！
工程啟示 (Slide 13)：透過編寫簡潔的模組化代碼 (Write code concisely)，可以顯著減少程序員閱讀代碼時的 Fixations 次數！

🤖 延伸考點：大語言模型 (LLM) 與 NLP 的語境缺陷 (Slides 35, 50)

  • Causal LM (因果語言模型 / Left Context Only, Slide 35)：
    現代 LLM 的 Causal masking / Causal self-attention 靈感正源於心理語言學家 Meyer & Schvaneveldt (1971) 的語義啟動實驗 (Semantic priming experiments)！
    例如："Charlotte eats her noodles with _____" → 前文語境 eats noodles 啟動了食物關聯，讓你選出 spicy oil / garlic oil，而排除掉機械用的 motor oil (機油)！
  • Azure Machine Learning 的尷尬翻車 (Slide 50)：
    學生發郵件給 Hoorn 教授說："我成了密切接觸者，上週五和確診的博士生吃過飯，這一週不能見人了。"
    結果 Outlook 的 AI 自動回覆建議居然彈出：[Congratulations!] [Good to hear!] [Great news!] — 因為低階 NLP 只抓到了局部詞彙 tested negative and doing well，卻對整體語境毫無概念 (No clue about context)！

  • 畫圖還是寫字？(Slide 52)：在舊版 PowerPoint 中，你想插入文本框寫字 (Write)，卻必須去勾選 View > Toolbars > Drawing (繪圖)。

  • Ambiguity (一詞多義) vs. Synonyms (多詞同義, Slide 57)：
    • Ambiguity：1 個詞指向多個不同意思（如 Scenario Manager）。
    • Synonyms：多個不同詞卻指向同一個意思/同一個視窗（例如桌面上叫 Properties，右下角托盤卻叫 Options，點開居然是同一個視窗！或者 Trash / Bin / Recycle / Deleted items 混用）。切記：界面中絕對不要混用同義詞 (Don't use synonyms, Slide 68)！
  • Blackboard 的 Open 陷阱與接近性違規 (Slides 66-67)：選單裡寫著 Open，點了卻是下載文件；而且勾選框在最左下角，下載按鈕卻在十萬八千里外的最右上角！

🎨 Typography 字體排印黃金法則與 CRAP 視覺設計四原則 Slides 69 - 75

✒️ 1. SD Communication Design 字體排印規範 (Typography, Slide 69 · 必考數字！)

  • 襯線 vs 無襯線：Serif (襯線體) 在紙質印刷品 (in print) 中更易讀；Sans-serif (無襯線體) 在電腦螢幕 (on screen) 上更易讀且更休閒。
  • 比例字體與大小寫：Proportional fonts (比例字體) 比等寬字體更省空間且更易讀；Mixed-case (大小寫混合) 比全大寫更緊湊易讀。
  • 每行字數上限：印刷品每行最多 60 個字符 (at most 60 characters long)。
  • 🔥 嚴格數量限制 (1-2-2-4 法則)：最多 1~2 種字體 (上限 3 種)、2 種傾斜度 (normal, italic)、2 種粗細權重 (normal, bold)、4 種字號大小 (title, subtitle, text, footnote)。
  • 最小字號差：不同層級字號之間至少要相差 2 pt (at least 2 pt) 肉眼才能區分！
  • 色彩與背景：慎用藍色文字（藍光閱讀敏銳度最低）；背景應使用中性色 (黑、白、灰)。切勿使用垂直旋轉 90° 的文字排版！

📐 2. CRAP 界面排版四大原則與 Grids 網格系統 (Slides 70 - 75)

  • C — Contrast (對比)：Make different things different! 突出主導元素 (Dominant elements)，弱化次要元素。
    ⚠️ 恒生銀行反例 (Slide 71)：用戶只想找右上角小小的 Logon 登入，結果視覺焦點全被中間巨大的紅底 Apply now 和 1.78% 貸款廣告搶走了！
  • R — Repetition (重複與一致性 Consistency)：在整個界面中重複一致的位置、格式與組件風格。
  • A — Alignment / Create Unity (對齊與統一性)：透過水平與垂直網格線 (Grids, Slides 72-73) 對齊相關組件，創造視覺流 (Visual flow)。
  • P — Proximity (接近性)：將相關元素靠近分組 (Group related elements)，用留白 (White space) 隔開無關元素。
  • 圖標設計黃金法則 (Icons, Slide 75)：除極少數最熟悉的圖標外，永遠要給圖標加上文字標籤 (Always label your icons)！把圖標歸入「家族 (Icon families)」；圖標的剪影輪廓 (Silhouette) 傳遞最多信息；遵循識別優於回憶 (Recognition over recall)；先用黑白設計，最後再上色 (Design first in b/w, add colour later)！

🤯 交互實驗 5A：Microsoft Image Composer 的「五重否定」崩潰彈窗 (Slide 85)

當你正在刪除一個圖形精靈 (erasing a sprite = 第1重否定：抹除存在) 時，系統彈出以下警告：

Microsoft Image Composer

👆 假如你想「保留 Undo 功能（也就是不繼續刪除）」，你該點 Yes 還是 No？點擊上方按鈕試試看！

• 設計鐵律：永遠保持陳述句為肯定句 (Affirmative)，讓用戶的按鈕來提供否定（No / Cancel / Quit）！

🏛️ 界面恥辱堂經典案例速覽 (Slides 76 - 93)

  • 假選擇與死循環 (Slides 76-79)：① "You are about to overwrite the original file. Go ahead?" 卻只給一個 [OK] 按鈕（毫無選擇權！）；② 正在 Cancelling... 的進度條旁邊放一個 [Cancel] 按鈕（取消一個正在取消的操作會怎樣？）；③ "Failed to check out file. The error was: No error occurred." 或 "NetInfo read failed! (Operation succeeded)"（自相矛盾！）。
  • 中國移動香港 CMHK 短信災難 (Slide 80)：
    • 違背接近性偏見 (Violation of proximity bias)：把 3~4 條獨立信息不加空行黏成一整段；
    • 誤用定冠詞 "the" (Misuse of the article 'the')：剛說完「您 HK$206 的付款已收到」，緊接著同一段寫 "You can view the bill details and pay the bill"！在同段中 the 是指向性詞 (Deictic element)，指代剛才那張已付過的特定帳單，導致用戶困惑「我不是剛付完嗎？！」（應區分特定 Specific 與泛指 Generic）。
  • Ryanair 瑞安航空暗黑模式 (Dark Pattern, Slide 82)：買機票時問需不需要旅遊保險，竟然把 [Don't Insure Me (不投保)] 藏在「選擇居住國家 (Select a country)」下拉選單的 Denmark (丹麥) 和 Finland (芬蘭) 之間！
  • 漢堡點餐與 City Super 購物車 (Slides 83-84)：漢堡預設不加配料卻逼人勾選「No toppings」，底部又有個全加的「All the Way」；City Super 購物車有 80 件商品，彈窗只寫 "Your desired quantity is unavailable [Ok]" 卻不告訴你是哪一件商品缺貨 (WHICH ITEM?!?!)！
  • 同義反覆的廢話 Tooltips (Full Circle, Slides 92-93)：滑鼠懸停在 Properties 上顯示 "Show the properties..."；懸停在 Manage Quick Steps... 上顯示 "Create, edit, delete, and rearrange quick steps" — 邏輯上沒錯，但用戶依然不知道什麼叫 Quick steps！
