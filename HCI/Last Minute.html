💥 2. 三大災難案例 + KLM 退票案 (必考！)

  • Mizuho 日本瑞穗證券烏龍指 (Fat-finger syndrome)：壓力下按錯小按鍵（1股61萬變61萬股1元），證交所系統無法撤銷 (No cancel)，損失 3.31 億美元。
    👉 Exam Sample Item (Lec 2 P.59)：與 Fitts' Law 的關係是 D: A and B are correct（A. 壓力惡化表現 Stress worsens performance + B. Fitts 考慮指標與目標的寬度比例 width ratio between pointer and widget）。
  • AA965 空難 (Cali Accident)：輸入 'R' 想去 ROZO 卻導航去 ROMEO，缺乏選定信標的反饋 (No feedback on chosen beacon)，且加速時未自動收起減速板。官方怪機師，實為 Poorly designed HCI。
  • Three Mile Island 三哩島核災 (Harrisburg)：
    ❌ 四大罪狀：1. 指示燈假陽性 (Malfunction of indicator / False positive)；2. 1500 個警報 (Information overload)；3. 標籤擋住燈 (Human error / Tag in front)；4. 警報靜音鍵無彈性 (Inflexible alarm system)。
    ✅ 四大改善原則 (必背！)：Offer informative feedback、Reduce short-term memory load、Offer error prevention、Support internal locus of control。
  • KLM 與 Expedia 機票無預警取消案 (Lec 1 P.20–24)：證明 HCI 不只是介面設計，還包含 Customer journey, organization of work, task delegation, business processes, algorithms。

🎯 2. Fitts' Law 互動模擬器 (Lecture 4 核心！)

公式：$T = a + b \log_2(2D/W)$ 或 Shannon 版 $ID = \log_2(D/W + 1)$，效能指標 $IP = 1/b$。
⚠️ 鐵律：ID 只取決於任務 (D 和 W)，與設備無關；常數 $a, b$ 才取決於設備！

👁️ 1. 視覺生理與 3D 運動感知 (Lecture 5)

  • Rods (桿細胞)：負責低光暗視覺 (Low-light vision)。
  • Cones (錐細胞)：負責色彩視覺。Blue acuity is lowest (藍色敏銳度最低)；8% 男性與 1% 女性色盲。
  • Ganglion cells (神經節細胞)：作為 Pattern filters，中頻率 (Middle frequencies) 通過最好；具備 Mutual suppression (相互抑制) 機制 $\rightarrow$ 解釋了 Hermann Grid 交叉口看到灰點 以及 紅配青互補色視覺殘留 (After-images)。
  • Optic Flow (光流)：Expanding (擴張) = 感覺前進 (身體前傾 Lean forward)；Contracting (收縮) = 感覺後退 (身體後仰 Lean backward)。
  • Retinal Path & Motion Parallax (運動視差)：近處的狗視網膜移動路徑長 (跑得快)，遠處的月亮路徑短。物體從視野同側離開 = 感覺跟著你走；從反側離開 = 感覺留在後面。
  • 斑點狗 (Dalmatian Dog) 為什麼人類認得出、AI 認不出？
    👉 黑點只是 unconnected data points。人類靠 Closure (封閉性) 與記憶中的 Concept-driven (頂層概念驅動) 填補空白；AI 只是底層像素/邊緣匹配。

🎨 2. Gestalt 格式塔 7 大知覺原則視覺化

① Proximity (接近性)

距離近的自動歸為一組（左2直欄、右2橫排）

② Similarity (相似性)

形狀/顏色相同的自動歸為直欄

  • ③ Symmetry (對稱性)：對稱圖形被視為整體前景（如西洋棋剪影）。
  • ④ Continuity (連續性)：視線傾向沿著最平滑的路徑 (Smoothest path) 延伸。
  • ⑤ Closure (封閉性)：大腦自動忽略缺口補全熟悉圖形（如 Kanizsa 三角形、IBM 條紋 Logo）。
  • ⑥ Smallness (小面積原則)：小面積區域易被視為前景 (Figure)，大面積視為背景（如魯賓之杯）。
  • ⑦ Surroundedness (包圍性)：被包圍的區域易被看作獨立圖形（導致一開始看不出黑塊中間白色的 "TIE" 字）。

📋 2. Tutorial 5：需求工程必考對比

  • Requirement (需求) = 利益相關者的需要 (What the software should do)。
  • Specification (規格) = 經過分析後的技術文檔，描述軟體特徵與行為 (How that need will be met)。
  • Functional Requirement (功能需求)：用動詞 (Verbs) 描述系統做什麼。
    ✅ 例："The system shall verify the student's 6-digit pickup code."
  • Non-functional Requirement (非功能需求)：用形容詞/可量化指標描述系統品質（Usability / Performance / Security）。
    ✅ 例："The interface must be easy to learn so a novice can check in within 60 seconds."
  • PACT 框架：People, Activity, Context, Technology。

🛠️ 3. Tutorial 1, 3, 6：定律與測試指標

  • Miller's Law：短期工作記憶容量 = 7 ± 2 chunks。
  • Hick's Law：選單選項增加，決策時間呈 對數增加 (logarithmic increase)。
  • Norman's Gulf of Execution (執行鴻溝)：用戶不知道該按哪裡才能達成目標。
  • Maze 原型測試 3 大指標 (Tut 3)：
    1. Direct Success：走預期路徑完成任務；
    2. Indirect Success：走非預期路徑但仍到達終點畫面；
    3. Give-up / Bounce：中途放棄離開。
